# M15 赛果因子赋权与实验模型计划

状态：实现与回溯执行完成（2026-10-09）；所有 M13A 候选因子组全部保留，不做因子筛除。研究结果不足以替换默认 baseline。

## 1. 目标与边界

为 MatchQuant 增加一个可复现的实验性 1X2 因子模型，使用 M13A 赛前因子预测主胜、平局、客胜，并与当前 Elo K32 baseline 做受限概率融合。模型作为单独的 M15 研究入口，不替换 M1–M12 默认预测、M3 选择结果、现有预测 schema 或发布包。历史表现未达预注册门槛时，运行结果仍以 baseline 概率为准。

本阶段不接入新闻、赔率、伤停、外部联网数据、Sites 页面或 GitHub 推送；也不把回测写成未来胜率、因果关系或盈利证明。

## 2. 因子与赋权方法

全部纳入以下 12 类逐队数值输入，主队与客队分别保留，共 24 个原始特征：

- 赛前 Elo rating；
- 近 5 / 10 场积分率；
- 近 5 / 10 场进球均值与失球均值；
- 近 5 / 10 场对手批前 Elo 均值；
- 主队主场、客队客场的收缩进球均值与收缩失球均值；
- 日历日休息间隔。

所有 M13A 数值因子列进入模型，不根据单变量相关、验证表现或系数大小删列。再为每个输入加入缺失指示列；缺失值用训练集列中位数填补。未知队伍或整侧状态不可核实的比赛保留在预测行和覆盖报告中，但因 M13A 明确标记 `unknown_team` / `needs_review`，融合权重强制设为 0，该场使用 baseline。

赋权采用三分类多项逻辑回归（softmax）。每个结果类别都有一套系数，权重直接来自带 L2 正则的最大似然拟合；不对回归系数施加“因子应为正”的主观限制。训练集内计算中位数、均值和标准差并保存，验证集、测试集和未来查询只复用这些统计量。常数列缩放设为 1。截距不受惩罚。拟合使用仓库已有 NumPy，不引入 sklearn/scipy。

L2 惩罚候选预注册为 `0.01, 0.1, 1, 10`。它保留全部输入，同时压低高度相关因子的系数方差；若系数趋近零，作为该训练和正则设置下贡献有限的诊断，不解释成因子已被删除。

候选概率记为 `p_factor`，冻结 baseline 概率记为 `p_elo`，最终实验概率为：

```text
p_final = (1 - w) * p_elo + w * p_factor
w ∈ {0.00, 0.05, 0.10, ..., 0.50}
```

只在验证折上联合选择 L2 惩罚与一个全局 `w`，主目标为 pooled multiclass Log Loss；平局时依次优先更强的正则、较小的 `w`。`w=0` 是明确 baseline 候选。正式测试或无效因子行不能参与选择。

## 3. 时间与数据合同

- 因子面板按 MatchQuant `_timeline` 同一时间批次构建：先为该批所有比赛冻结同一批前状态，再更新该批比分；同一日期的比赛不得互相泄漏。
- 复用 M13A 的 Elo、窗口、场地收缩、休息日公式及 `fixture_team_factors` / `flatten_fixture_factors`；不能逐场重建完整历史快照。
- 训练、验证、测试都保留 canonical 历史的每一行；不能按 M13A ready 状态或赛果删样本。记录唯一 `match_id`、分区、因子缺失、未知队状态与 fallback 原因。
- 使用现有评估合同：训练标签来自首个验证期之前；验证为 2022-23、2023-24 两个按时间排列的赛季；候选选定后，可将验证期标签加入最终重拟合，再对 2024-25 运行一次最终回溯评估。
- 2024-25 已被既有工作查看，故该次结果只能标记 retrospective，不能称 untouched test，不能用于无偏采用结论。2025-26 暴露未确认，不作新 holdout。新的前瞻证据须先锁定未来预测文件和模型配置，再等待结果。
- 使用本地明确的 CSV 与 processed manifest，核对路径、哈希、行数、列、cutoff 和数据版本；不刷新、不 apply、不联网。当前归档数据上游获取时间未知，报告需保留此限制。

## 4. 实验流程与可复现输出

增加独立 API 和 `result-factor-model` CLI：

1. 验证 canonical history 与 manifest；
2. 按批次构建一个赛前因子面板；
3. 在训练分区拟合完整的 lambda 网格；
4. 对两个验证折生成 baseline、因子模型、受限混合概率，选择 `(lambda, w)`；
5. 以训练期加验证期重拟合所选因子模型；
6. 对最终测试期仅评一次并写入明确标注“回溯研究”的报告；
7. 写唯一输出目录，保存 evaluation contract、输入证据、全部搜索网格、模型参数/训练缩放量、逐场预测与缺失/fallback 标志、分赛季指标及汇总报告。

报告至少包含样本数、coverage、baseline/因子/融合的 Log Loss 与 Brier、Accuracy 辅助指标、按赛季与实际主/平/客结果分组的指标、缺失与 fallback 数、`lambda` 与 `w` 的选择过程、输入哈希/cutoff，以及研究暴露和数据限制。最终测试另提供固定 seed=20261009、1000 次自然周配对 bootstrap 的 ΔLog Loss/ΔBrier 区间，只作已暴露回溯数据上的描述，不用于采用检验。概率输出须有限、位于 `[0,1]` 且和为 1；这不等于校准通过。

输出仅放在仓库外的显式研究结果根目录；不得写回 canonical 数据、active pointer、Git 或发行包。预测 CSV 属本地派生数据，不提交。

## 5. 兼容与失败处理

- 现有 `models.py` 的正式模型注册表和默认模型不变；M15 模型不进入 M1–M12 或 runtime bundle。
- M13A 不可核验、数据 manifest 不匹配、训练结果单类、数值不收敛或时间折冲突时，命令明确阻断，不生成“已完成”结果。
- M13A 未知队、因子行结构无效或候选概率不合法时，该场回退 Elo baseline 并记录原因；部分普通因子缺失时使用训练集中位数和缺失指示。
- 冻结参数对未知队/不可核验行的 `w=0` 保证其三类概率逐项与 baseline 完全相等。
- 验证结果无改善、`w=0` 最优、测试证据不充分或工程门槛未通过，结论为继续保留 baseline 默认，只保留 M15 实验模型和报告。

完成判定分三项报告：

1. **工程**：输入证据正确、严格批次无泄漏、拟合和 fallback 可重复、测试通过、现有模型 API 不变。
2. **研究**：只描述本次 retrospective 的指标；历史 test 已暴露，不能据此声称新模型泛化或达成无偏采用门槛。
3. **覆盖**：显示现有归档覆盖 cutoff 与上游时间未知；不要声称实时或完整赛程覆盖。

通过工程验收不等于采用新模型。若没有前瞻锁定证据，默认预测仍使用 baseline。
