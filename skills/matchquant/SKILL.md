# MatchQuant Agent Skill: 英超单场量化分析与按需数据同步

## 1. 技能概述与定位

本 Skill 为宿主 Agent 提供专业级英超足球量化研报与盘口定价效率分析能力。
- **职责划分**：宿主 Agent 负责自然语言交互、参数确认、工具编排、解释叙事与追问回答；MatchQuant 底层引擎负责数据源访问、快照校验、时序隔离、双轨建模（Track A 基本面 vs 市场盘口）与权威概率计算。
- **数值与防幻觉铁律**：Agent 严禁在 Prompt 中自行推算概率或修改底层模型输出。报告中的所有胜平负概率、进球期望、历史战绩、盘口去水胜率、Edge 与因子权重必须 100% 绑定自 MatchQuant 适配器返回的权威数值。
- **双轨隔离宪法**：Track A 纯基本面模型严禁输入任何博彩赔率；盘口数据仅用于独立的市场对照、让球深度解读、价值偏差（Value Edge）与时序资金流向（Steam Drift）追踪。

---

## 2. 激活时机与意图识别

在下列场景下激活本 Skill：
1. **纯基本面单场分析请求**：
   - “帮我分析一下这周末曼城对阿森纳”
   - “今晚切尔西主场打利物浦怎么看？”
   - “分析 2026 年 5 月 10 日曼联客场打维拉，按最新数据”
2. **包含实时盘口的单场分析请求（`use_live_odds: true`）**：
   - “带实时盘口分析一下切尔西对曼联”
   - “结合最新赔率和亚盘看看阿森纳对热刺”
   - “切尔西对曼联，拉取最新盘口并与模型对比”
3. **独立盘口拉取与快照存储（`action: odds`）**：
   - “拉取一下切尔西对曼联的即时盘口快照”
   - “查看这场比赛各大主流机构的最新开盘”
4. **数据同步与环境诊断（`sync` / `readiness` / `setup`）**：
   - “更新一下英超历史数据”
   - “检查 MatchQuant 本地数据就绪状态”
   - “初始化 MatchQuant 配置”
5. **已分析赛事的后续追问（`action: followup`，零重算只读证据）**：
   - **盘口与让球看法**：“盘口和让球怎么看？”
   - **模型与盘口差异**：“为什么模型和盘口差这么多？有背离吗？”
   - **时序与资金流向**：“赔率变化趋势和聪明钱走势怎样？”
   - **刷新盘口请求**：“帮我刷新最新盘口”（返回引导提示，严禁隐式重算）
   - **基本面逻辑与进球**：“为什么更看好主队？”、“两队进球预期是多少？”、“给个精简总结”

## 3. 参数解析与标准化规则

在调用适配器前，Agent 应按以下规则标准化用户输入的参数：

### 3.1 俱乐部名称解析
用户通常使用中文全称、简称或昵称。系统内置常见映射（可由用户 Profile 扩充）：
- 曼城 / 曼彻斯特城 → `Man City`
- 曼联 / 曼彻斯特联 → `Man United`
- 阿森纳 / 枪手 → `Arsenal`
- 利物浦 / 红军 → `Liverpool`
- 切尔西 / 蓝军 → `Chelsea`
- 热刺 / 托特纳姆热刺 → `Tottenham`
- 纽卡 / 纽卡斯尔联 → `Newcastle`
- 维拉 / 阿斯顿维拉 → `Aston Villa`
- 布莱顿 / 海鸥 → `Brighton`
- 森林 / 诺丁汉森林 → `Nottingham Forest`
- 狼队 → `Wolves`
- 西汉姆 / 铁锤帮 → `West Ham`

### 3.2 比赛日期与时序截止（as-of）
- 相对日期（如“今晚”、“明天”、“周六”）结合用户配置时区（默认 `Asia/Shanghai`）转换为确切 ISO 日期 `YYYY-MM-DD`。
- **时序防穿越铁律**：盘口快照时间必须严格早于预测截止日（`observed_at < as_of`）。
  - 当启用实时盘口且用户**未显式指定** `as_of` 时，系统自动将 `as_of` 设为盘口观察日次日（`observed_at + 1天`），确保零前瞻偏误；
  - 若用户显式指定的 `as_of <= observed_at`，系统触发防穿越保护，优雅降级为纯基本面 Track A 模式并在报告中显著标注。

### 3.3 赛季判定
英超赛季通常跨越 8 月至次年 5 月（格式 `YYYY-YY`，如 `2026-27`）。可由比赛日期推断，或显式传入。

## 4. 工具调用协议与工作流

Agent 通过执行适配器脚本 `scripts/run_adapter.py` 或调用 CLI `matchquant agent-adapter` 完成底层交互：

### 4.1 环境诊断与首次设置 (`setup`)
```bash
python scripts/run_adapter.py --request '{"action": "setup"}'
```

### 4.2 数据检查与按需同步 (`sync` / `readiness`)
```bash
python scripts/run_adapter.py --request '{"action": "sync", "apply": true}'
```

### 4.3 单场分析核心调用 (`analyze`)

#### A. 纯基本面分析（无盘口）
```bash
python scripts/run_adapter.py --request '{
  "action": "analyze",
  "home": "切尔西",
  "away": "曼联",
  "date": "2026-10-31",
  "season": "2026-27"
}'
```

#### B. 融合实时盘口分析（`use_live_odds: true`）
```bash
python scripts/run_adapter.py --request '{
  "action": "analyze",
  "home": "切尔西",
  "away": "曼联",
  "date": "2026-10-31",
  "season": "2026-27",
  "use_live_odds": true
}'
```
适配器执行流程：
1. 自动从盘口源（The Odds API / 本地快照）检索权威 1X2 与亚盘；
2. 校验时间戳并安全持久化快照至 `odds_snapshots/`；
3. 执行 Power 幂次法去水与 Value Edge 计算；
4. 检索历史序列生成 Steam Drift 变动趋势；
5. 生成包含完整 `[E5]` 市场对比章节的研报与 artifacts。

### 4.4 单独拉取盘口快照 (`odds`)
```bash
python scripts/run_adapter.py --request '{
  "action": "odds",
  "home": "切尔西",
  "away": "曼联",
  "date": "2026-10-31"
}'
```

### 4.5 针对已有 Run 的后续追问 (`followup`)
```bash
python scripts/run_adapter.py --request '{
  "action": "followup",
  "run_id": "match_report_2026-10-31_chelsea-man-united_xxx",
  "question": "为什么模型和盘口差这么多？"
}'
```
**追问红线约束**：
- 严格基于磁盘已有 JSON 证据回答（耗时 < 0.1s），返回 `recomputed: false`；
- 严禁触发重新拉取 API 或重新拟合模型；
- 若用户明确要求“刷新盘口”，必须返回引导提示，告知需发起新 run。

## 5. 报告输出规范

Agent 向用户交付报告时，应确保 Markdown 与 HTML 交付物结构与数字 100% 一致：
1. **统一六大章节结构**：
   - **一、 核心量化结论与概率分布 `[E1]`**：胜平负概率表、泊松进球期望、大 2.5 概率、Elo 基准参考
   - **二、 核心特征驱动与对位解析 `[E3]`**：权重最显著的 6 大因子及其利好倾向
   - **三、 近期战绩与场面技术统计 `[E4]`**：真实完成比赛统计（射正、角球，NaN 诚实留空）
   - **四、 市场参照与让球对位 `[E5]`**：
     - 有盘口时：盘口机构与观测时间、去水隐含胜率 vs Track A 偏离表、亚盘让球深度解读、价值偏差（Value Edge）、显著背离预警卡片（若偏差超阈值）、时序 Steam 漂移趋势、常驻免责声明
     - 无盘口或拉取失败时：诚实说明降级原因，重申 Track A 独立推断能力
   - **五、 数据版本与时序截断回执 `[E6]`**：严格时序隔离声明（as-of, used_data_cutoff, 账龄, 提前量）
   - **六、 客观局限性与免责声明**：无场外伤病/更衣室信息，不构成投注建议
2. **交付物链接**：提供生成的本地独立 HTML 报告（`agent_report.html`）与 Markdown 报告文件路径。

## 6. 盘口问答与背离解释范式

当用户追问市场盘口相关问题时，Agent 必须遵循以下量化归因范式：

1. **盘口态度与让球提问**：
   - 提取去水市场胜率与亚盘让球线（如“主让 0.25 球”）；
   - 结合 Track A 预期进球差（$\lambda_h - \lambda_a$），阐述机构盘口深度与基本面实力优势的吻合度。
2. **模型 vs 盘口显著背离提问**：
   - 列出具体赛果上的偏离百分点（例如“主胜基本面高出市场 5.2 个百分点”）；
   - 展示价值偏差（`Value Edge = P_model * Odds - 1`）；
   - **客观归因**：强调 Track A 专注于球场内在历史技战术与统计均值回归，而市场盘口可能吸收了场外动态（主力伤病、首发轮换、战意取舍、极端天气或资金热度）。分歧揭示统计视角与市场资金的差异，绝不代表模型必然正确。
3. **赔率变化趋势提问**：
   - 依据时序快照序列描述聪明钱流动方向（Steam Direction）及赔率/胜率漂移幅度；
   - 若仅有单时点快照，诚实陈述“暂无多时点序列，仅提供静态初盘基准”。
4. **刷新盘口提问**：
   - 明确回复本轮问答基于只读快照（零重算）；
   - 引导用户发起带 `use_live_odds: true` 的新分析请求以生成新 Run。
