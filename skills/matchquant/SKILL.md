# MatchQuant Agent Skill: 英超单场量化分析与按需数据同步

## 1. 技能概述与定位

本 Skill 为宿主 Agent 提供专业级英超足球量化分析能力。
- **职责划分**：宿主 Agent 负责自然语言交互、参数确认、工具编排、解释叙事与追问回答；MatchQuant 底层引擎负责数据源访问、快照校验、时序隔离、因子挖掘与权威概率计算。
- **数值与防幻觉铁律**：Agent 严禁在 Prompt 中自行推算概率或修改底层模型输出。报告中的所有胜平负概率、进球期望、历史战绩与因子权重必须 100% 绑定自 MatchQuant 适配器返回的权威数值。

---

## 2. 激活时机与意图识别

在下列场景下激活本 Skill：
1. **单场分析请求**：用户提到英超具体对阵，例如：
   - “帮我分析一下这周末曼城对阿森纳”
   - “今晚切尔西主场打利物浦怎么看？”
   - “分析 2026 年 5 月 10 日曼联客场打维拉，按最新数据”
2. **数据同步与诊断请求**：
   - “更新一下英超历史数据”
   - “检查 MatchQuant 本地数据就绪状态”
   - “初始化 MatchQuant 配置”
3. **已分析赛事的后续追问**：
   - “为什么模型更看好主队？”
   - “两队的期望进球是多少？大球概率高吗？”
   - “给我总结成一段精简的核心结论”
   - “这个盘口差异怎么理解？”

## 3. 参数解析与标准化规则

在调用适配器前，Agent 应按以下规则标准化用户输入的参数：

### 3.1 俱乐部名称解析
用户通常使用中文全称、简称或昵称。系统内置常见映射（可由用户 Profile 扩充）：
- 曼城 / 曼彻斯特城 → `Man City`
- 曼联 / 曼彻斯特联 → `Man United`
- 阿森纳 / 枪手 → `Arsenal`
- 利物浦 / 红军 → `Liverpool`
- 切尔西 / 蓝军 → `Chelsea`
- 热刺 / 托特纳姆热刺 → `Tottenham`
- 纽卡 / 纽卡斯尔联 → `Newcastle`
- 维拉 / 阿斯顿维拉 → `Aston Villa`
- 布莱顿 / 海鸥 → `Brighton`
- 森林 / 诺丁汉森林 → `Nottingham Forest`
- 狼队 → `Wolves`
- 西汉姆 / 铁锤帮 → `West Ham`

### 3.2 比赛日期与时序截止（as-of）
- 相对日期（如“今晚”、“明天”、“周六”）结合用户配置时区（默认 `Asia/Shanghai`）转换为确切 ISO 日期 `YYYY-MM-DD`。
- 预测截止日 `as_of` 默认等于比赛日 `date`（日初语义，当天比赛绝不计入历史特征）。
- 若用户明确要求“按某日之前的数据”，传入显式 `as_of`。

### 3.3 赛季判定
英超赛季通常跨越 8 月至次年 5 月（格式 `YYYY-YY`，如 `2025-26`）。可由比赛日期推断，或显式传入。

### 3.4 模糊信息消歧
- 若用户仅说“今晚那场强强对话”且存在多场可能，请一次性提出清晰单选列表，不要盲目猜测。
- 未连接官方赛程前，明确标注比赛为用户指定对阵。

## 4. 工具调用协议与工作流

Agent 通过执行适配器脚本 `scripts/run_adapter.py` 或调用 CLI `matchquant agent-adapter` 完成底层交互：

### 4.1 环境诊断与首次设置 (`setup`)
```bash
python scripts/run_adapter.py --request '{"action": "setup"}'
```
检查 Python 解释器、依赖包（numpy, pandas, scipy）、数据路径可写性及当前数据集指针。

### 4.2 数据检查与按需同步 (`sync` / `readiness`)
- 用户配置了 `auto_refresh: true` 时，单场分析前若发现数据陈旧或缺失，适配器会自动执行安全的 `addition-only` 增量更新。
- 手动请求同步：
```bash
python scripts/run_adapter.py --request '{"action": "sync", "apply": true}'
```

### 4.3 单场分析核心调用 (`analyze`)
```bash
python scripts/run_adapter.py --request '{
  "action": "analyze",
  "home": "曼城",
  "away": "阿斯顿维拉",
  "date": "2026-05-15",
  "season": "2025-26"
}'
```
适配器返回结构化 JSON，包含：
- `status`: `ok`（完整）或 `needs_review`（如陈旧数据回退）
- `predictions`: Track A 胜平负概率与期望进球
- `artifacts`: 生成的权威 JSON 及 Markdown/HTML 报告路径
- `temporal`: 严格的时序截断回执

### 4.4 针对已有 Run 的后续追问 (`followup`)
```bash
python scripts/run_adapter.py --request '{
  "action": "followup",
  "run_id": "M13A_20260515_xxx",
  "question": "为什么看好主队？请结合攻防对位说明"
}'
```
适配器直接读取已有 `report.json` 并检索证据，无需重复进行耗时的数据切片与模型拟合。

## 5. 报告输出规范

Agent 向用户交付报告时，应严格遵循以下要求：
1. **篇幅与结构**：约 800 - 1,200 字，分为：
   - 核心量化结论与胜平负概率表格（含期望进球与大 2.5 概率）
   - 核心量化特征驱动与对位解析（引用证据 ID，如 `[E1]`, `[E3]`）
   - 近期战绩与场面攻防统计（如射正、角球，缺失统计诚实标注）
   - 市场参照对比（若有初盘数据）
   - 时序截断回执（数据截止日、数据账龄、提前量）
   - 客观局限性声明（无突发伤病/更衣室新闻，不构成投注建议）
2. **交付物链接**：提供生成的本地独立 HTML 报告与 Markdown 报告文件路径，便于用户离线查阅。
